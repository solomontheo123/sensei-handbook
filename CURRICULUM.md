# CURRICULUM

> **The Frontend Engineering Learning Roadmap**
>
> A structured curriculum for developing the knowledge, skills, habits, and engineering mindset required to become a professional frontend engineer.

---

# Purpose

This document defines the long-term learning roadmap that accompanies the SENSEI Handbook.

Unlike traditional learning paths that focus on completing courses or memorizing frameworks, this curriculum is designed to build engineering competence progressively.

Each phase builds upon the previous one.

The goal is not simply to finish the curriculum, but to develop the ability to design, build, maintain, and continuously improve production software.

---

# Learning Philosophy

This curriculum is guided by a few fundamental principles.

- Learn concepts before tools.
- Understand before memorizing.
- Practice before moving forward.
- Build projects to reinforce knowledge.
- Review regularly.
- Document lessons learned.
- Learn continuously.

Progress is measured by understanding and application rather than the number of completed tutorials.

---

# Learning Objectives

Upon completing this curriculum, I should be able to:

- Design frontend architectures.
- Build scalable React and Next.js applications.
- Write maintainable TypeScript.
- Consume and design APIs confidently.
- Work effectively with authentication and authorization.
- Manage client-side state efficiently.
- Debug production issues systematically.
- Collaborate using professional Git workflows.
- Review code with confidence.
- Deploy production-ready applications.
- Learn unfamiliar technologies independently.

---

# Curriculum Structure

The curriculum consists of twelve sequential phases.

Each phase contains:

- Learning objectives
- Core topics
- Practical labs
- Mini projects
- Review checkpoints
- Completion criteria

A phase should not be considered complete until both the concepts and practical work have been mastered.

---

# Phase 1 — Engineering Foundations

## Goal

Develop the foundational skills required to work effectively as a software engineer.

## Topics

- Linux fundamentals
- Terminal usage
- File system navigation
- Git fundamentals
- GitHub workflow
- VS Code and development environment
- Networking basics
- HTTP fundamentals
- Command-line productivity

## Labs

- Install and configure Ubuntu.
- Customize the development environment.
- Create and manage Git repositories.
- Practice branching and merging.
- Use terminal commands without relying on graphical interfaces.

## Completion Criteria

- Comfortable using Linux daily.
- Confident with Git basics.
- Able to troubleshoot common environment issues.

# Rules for Progression

- Do not skip phases.
- Finish practical work before advancing.
- Build projects regularly.
- Review previous topics frequently.
- Document lessons learned.
- Prioritize understanding over speed.

---

# Measuring Progress

Progress is measured by the ability to:

- Explain concepts clearly.
- Solve unfamiliar problems.
- Design maintainable systems.
- Build production-ready applications.
- Teach others confidently.

Knowledge becomes mastery when it can be applied consistently.

---

# Success Criteria

This curriculum is complete when I can confidently:

- Design software before coding.
- Build production-ready frontend applications.
- Review engineering decisions critically.
- Learn new technologies independently.
- Mentor other engineers.
- Continuously improve both my software and myself.
